# 可被搜索性诊断器 · 本地网页版

> 上传简历 + 目标 JD，得出「招聘方字面能不能搜到你」，并给出带简历原文依据的改写建议，
> 一键导出改写后的 Word。
>
> **所有数据留在本机。整条流程只有一件事会联网：调用你在 `sk/apikey.txt` 里配置的模型 API。**

---

## 一、怎么用（三步）

### 1. 填 API Key

打开 `sk/apikey.txt`，在注释块下面粘贴一行：

```
sk-你的key
```

Key 在 https://platform.deepseek.com → 「API keys」里创建，充 10 元够跑几百份 JD。

> 图片（png/jpg）需要**视觉模型**，DeepSeek 的对话模型看不了图。要用图片就再加三行：
> ```
> VISION_MODEL=qwen-vl-max
> VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
> VISION_API_KEY=sk-你的dashscope密钥
> ```
> 不配也行——txt / pdf / docx 都能正常用。

### 2. 双击 `启动.bat`

它会自动：检查 Python → 首次安装 PDF 依赖（需联网一次）→ 启动本地服务 → 打开浏览器。

打开后地址是 `http://127.0.0.1:8765/`。

### 3. 传两个文件，点「开始诊断」

- ① 你的简历
- ② 目标岗位的 JD

支持：`pdf` `docx` `txt` `md` `png` `jpg` `webp`（图片需视觉模型）

## 二、你会看到什么

| 区块 | 内容 |
|---|---|
| **覆盖率卡片** | 精确覆盖（字面能搜到）/ 宽松覆盖（换个说法可达）/ 职位名对齐 |
| **关键词表** | 招聘方在找的每个词：哪一层、来自规则库还是模型、必需还是加分、命中/只缺词/真缺 |
| **模型的岗位理解** | 一句话说清这个岗位实际在做什么 |
| **国内平台写法提示** | BOSS / 猎聘上这些词通常怎么写（规则库给不了的东西） |
| **可以补** | 每条带「加在哪 / 怎么改 / 依据哪句简历原文」，可勾选 |
| **不要补** | 简历里没有事实支撑的词，硬加会在面试被追问时崩 |
| **生成 Word** | 按 JD 重构：换引导短语、调顺序、融关键词，并显示**改前 → 改后**覆盖率 |

### 补充信息（可选 —— 不填也能直接生成）

诊断结果出来后，页面下方还有一个「补充信息」区，两块都是可选的：

**① 你想额外强调的关键词**

看完结果，如果还有你觉得该突出、但工具没列出来的词，自己加进去（逗号分隔可一次加多个）。

**② AI 想跟你核实的问题**

针对工具判定「真缺」的关键词，模型会反问你 3–5 个具体问题，例如：

> **AI培训**　你有没有给同事或同学做过 AI 工具的使用培训或分享？

规则很硬：

| 你的操作 | 结果 |
|---|---|
| 回答「有 / 做过」并写了事实 | ✅ 才允许写进简历 |
| 回答「没有」 | ❌ 不写 |
| **留空不答** | ❌ **绝对不写** |

这一块存在的意义：工具只能从简历字面判断「你没做过」，但它不知道你**做过只是没写**。
由你自己确认，比模型猜要可靠得多。

## 三、数据在哪

| 内容 | 位置 |
|---|---|
| 上传的原始文件 | `web/uploads/`（`.raw` 原文件 + `.txt` 提取出的文字） |
| 导出的 Word | `web/outputs/` |
| 模型响应缓存 | `sk/_cache/`（同一份 JD 重跑不再花钱） |

这三处都已写进 `.gitignore`，不会被推到 GitHub。

**隐私边界**：
- 服务只监听 `127.0.0.1` —— 同一局域网的其他电脑访问不到
- 页面零外链（没有 CDN、没有字体服务、没有统计脚本）
- 除了调用你配置的模型 API，没有任何网络请求

## 四、文件结构

```
启动.bat                 一键启动（GBK 编码，中文不会乱码）
web/
  server.py              本地服务（标准库 http.server，零依赖）
  docgen.py              结构化数据 → DOCX（手写 OOXML，不装 python-docx）
  static/index.html      单页前端（原生 JS，零框架、零外链）
  uploads/               你的上传（自动创建，gitignore）
  outputs/               导出的 Word（自动创建，gitignore）
sk/
  kwlib.py               关键词库 + RELATED 锚点表（算分靠它）
  core.py                归一化 / 匹配 / 打分
  v2.py                  LLM 抽词 + 建议生成 + 锚点复核
  llm.py                 极简 API 客户端（urllib，不装 openai 包）
  prompts.py             两个 prompt
  apikey.txt             你的 Key（gitignore）
```

## 五、设计上的两条硬规矩

### ① 算分只用规则库，模型只负责"理解"

模型抽的词是 JD 原话（`技术方案撰写`、`客户需求分析`），
这类长短语字面几乎不可能在简历里原样出现。**把它们放进分母，覆盖率会直接被打成 0%**，
数字失去区分度、也没法和历史数值对齐。

所以：**规则库的词算分（短词、有锚点、可复现），模型的词只做展示和建议来源。**

### ② 每条建议必须有"锚点"，且由代码逐字复核

模型很擅长编一个"看起来很合理"的简历原文片段。所以每条建议都要求它给出 `anchor`，
代码去简历原文里逐字查找——**找不到就降级进「不要补」**。

⚠️ 但要知道这个护栏的边界：**它只做字面校验，不保证语义成立。**
模型可能拿「写文档」去支撑「培训」——字面找得到，意思不对。这层判断必须你自己做。

## 六、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 双击 bat 一闪而过 | 没装 Python，或安装时没勾 "Add Python to PATH" |
| 页面打不开 | 黑窗口是不是关掉了？关掉窗口 = 停止服务 |
| PDF 上传报错 | 首次装依赖失败。手动跑：`python -m pip install pdfplumber -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 图片上传报错 | 没配视觉模型，见第一节；或直接把图里的文字复制粘贴进输入框 |
| 「没有配置 API Key」 | `sk/apikey.txt` 里那行没粘对（不能有引号、空格、中文说明） |
| 想换端口 | 启动前设 `set APP_PORT=9000` |
| 想重跑不花钱 | 同一份 JD 会自动命中 `sk/_cache/`，删掉该目录即强制重新调用 |
